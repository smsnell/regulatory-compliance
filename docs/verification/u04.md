## Implementation and use

`rci.evidence.EvidenceStore(root, run_id, providers=None)` works inside an
existing isolated run root. The caller holds the U03 `runtime.writer_lock` and
serializes acquisitions. `acquire(source_id, original_locator, adapter, read)`
persists start before calling `read()`. The callback returns keyword arguments
for `finish`; adapters are deferred to U05. There is no fixture/fallback selector.
`start`/`finish` also support explicit dispatch boundaries. The returned attempt
and primary capture use the unchanged G1 schema and fresh Stage 02 record IDs.

The journal stores exclusive `analysis/attempts/<key>.start.json` and
`<key>.terminal.json` files, each carrying `rci-attempt-journal/1`, run, phase,
and attempt. Only terminal events are acquisition outcomes. Start fields are
provisional and do not establish retrieval. Terminal events also carry capture
or null and technical diagnostic or null. Exclusive writes and file/directory
fsync preserve append-only behavior; no event or retained content is rewritten.
The directory format avoids appending to a truncated JSONL tail. It is a local
U04 storage format, not a change to frozen snapshot or history contracts.

Before content/terminal persistence, the writer durably creates
`analysis/attempts/<key>.incomplete.json`, a `rci-attempt-write/1` control carrying
run/key, stage/source/output, reason, recovery action and an explicit unknown
next owner. Any such entry, including empty, malformed or dangling-symlink
entries, rejects inventory and claims. A valid-looking terminal cannot override
it. The control is removed only after the terminal file and directory fsyncs
succeed. Journal events and source bytes are never removed or rewritten.

Control removal is deliberately not followed by another fsync: the terminal is
already durable, and a crash can at worst restore the control and conservatively
reject the attempt. This avoids a final synchronization error after the only
incomplete indicator has been removed. Inspection never clears controls or
repairs an old attempt; an incomplete occurrence requires a fresh run. The marker
is local write coordination, not a terminal outcome or package-recovery journal.

`inventory()` rereads the journal, checks every start/terminal pair, original
identity/time/locator, exact G1 run/stage/type/suffix bindings and unique IDs for
both attempts and captures, metadata, null behavior, MIME,
chronology, capture bindings and actual bytes. Any pending, malformed,
cross-run or damaged attempt rejects freeze. No inventory result is a package
success or a verified source identity/legal finding.

`finish` hashes only the supplied permitted representation. Extracts require
method, source locator and permission basis. Redaction/extraction occurs before
storage; the hash never purports to identify an unretained original. Unknown
MIME is `application/octet-stream` with `content_type_known: false`. Zero bytes
have a real retained file/hash; no response has null content/path/hash. Returned
unsuitable/login/stale/unverified/unused bytes are preserved independently of
selection. Version metadata and effective locator remain caller-supplied or null.
The same extract-metadata validator runs during writing and independent journal
reading; missing, empty, whitespace-only and non-string required fields reject.

`claim` returns a G1 evidence record binding capture ID, exact file/hash,
assertion, quoted support and a typed locator. It checks a verified journal
capture and text quotations against retained UTF-8 bytes; the caller inserts
this record in Stage 02. Binary/visual meaning and extract fidelity remain U08.
There is no automatic claim generation or source interpretation.

Lexical path checks reuse G1. Directory descriptor traversal with `O_NOFOLLOW`
also rejects symlinks inside the root; source files are opened exclusively.
Failed/partial files remain preserved but are never bound as complete captures.
Technical diagnostics retain stage, source/output, failure type, reason,
recovery action and next owner (null when unknown), separately from content.
Exception text is not copied because it may contain credentials.

Read exceptions, adapter-output failures and catchable read/capture interruptions
produce a terminal diagnostic where disk permits; control interruptions are
re-raised. If terminal persistence itself fails, the caller receives an error
and the durable start/available bytes remain incomplete. An uncatchable kill
cannot guarantee a terminal write; inspection rejects the pending or partial
journal instead of inventing an outcome or resuming an old read. Fresh-run
package recovery remains U18. This is the conservative G1/U03 interruption
boundary, with no automatic journal repair or output replacement.
