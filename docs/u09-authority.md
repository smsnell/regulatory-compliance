# U09 Stage 03 authority and timing

U09 ends at the immutable `03-authority-and-timing.json`. It establishes bounded
draft legal rule scope and timing prerequisites, or retains Legal-owned blockers.
It evaluates no system impacts, produces no final artifacts and sends nothing.

For a fresh attended capture/authority slice:

```sh
python3 regulatory-change-impact-brief/scripts/run.py --config config/review.json --capture-slice --authority
```

Authorized declared scope and retry options retain their U07 meanings. U09 implies
U08 linked-report capture for direct and CLI callers. The report interpretation
and authority interpretation flags select distinct exchange runs; combining them
is rejected before capture. Final production integration remains with later units.
The slice outcome remains blocked for missing stages 04–07 even when Stage 03's
authority analysis succeeds. `authority_status` and `authority_stage_complete`
report the Stage 03 result separately from full package acceptance.

The six legal/context sources are captured through existing read-only adapters.
`authority.project_legal` retains derived visible HTML text and exact evidence
before Stage 02 freezes. Plain UTF-8 text is retained directly. Script/style text
is excluded; original HTML remains captured with separate bytes/hash/time.
Binary/unreadable representations and login responses cannot become legal text.
`u09_legal` uses G1's existing extension boundary. Independent `validate_slice`
recomputes legal evidence and derivations against the journal, alongside unchanged
U07/U08 accounting. Earlier frozen two-stage runs remain valid and unchanged;
they require a fresh run to acquire legal evidence.

The restricted invoking skill reads only the packet's captured extracts and
[authority policy](../regulatory-change-impact-brief/references/authority-policy.md).
Python creates the same frozen `rci-interpretation-request/1` envelope, using
U08's packet builder, and retains its original packet plus a dedicated authority
copy. Instruction/reference/schema hashes and visible execution metadata bind
the exchange. Submission uses `stage.py submit-authority`; exact proposal,
request, response and failure diagnostics stay in `analysis/authority/`.
No model API client, source mutation, message delivery or calendar tools are added.

The frozen candidate fields are preserved. One binding candidate's
`timing_candidates` contains one JSON string conforming to the additive
`authority-basis.schema.json`. It records source identity/version/history and
relationship assessments, exhaustive component support, exception scope and
timing. OJ supplies the reviewed base act; AMEND must be verified as related,
unrelated or future; CONSOLIDATED requires a supported version relationship.
LAW is a reproduction to reconcile. TIME/FAQ can supply guidance context only.
Formal sources must have HTTPS EUR-Lex original and effective origins; a source
ID or authorized mirror does not grant official authority.
Every legal component must occur literally in its cited binding quote; all
source assessments must cite exact captured identity/version/relationship text.

`authority.evaluate` validates the frozen exchange and explicit prerequisites.
Guidance never supplies a binding component. Future/unrelated amendments cannot
support an obligation. Conflicting/unknown assessments, missing source/history,
missing role/predicates/exceptions, unsupported dates and corrupt bindings cannot
produce established formal rules. Candidate-specific blockers preserve other
independently supported bases; shared prerequisites and competing same-basis
claims withhold their dependent rules. Aggregate status remains blocked. Every
component uses the exact source capture whose version/history was assessed.
Valid guidance context may remain visible.
Technical corruption raises a failure and retains diagnostics instead of becoming
a legal conclusion. A host that exits without submitting also fails, preserving
its packet/logs without fabricating Stage 03. Source failure yields a blocked
Stage 03 without a model call.

The initial supported timing subset uses ISO dates literally present in binding
quotes, an inclusive start and a supported exclusive end. Assigned date
`2026-08-26` stays distinct from source publication, retrieval and effective dates.
Post-review retrieval is allowed; a later formal legislative version cannot
silently substitute for historical authority. A future amendment can be retained
and explicitly excluded. Later explanatory guidance remains context. Intraday or
unknown precision remains blocked pending Legal's date-level interpretation;
no midnight cutover/timezone is inferred. Non-ISO date spelling, unidentifiable
requested selectors and missing version history remain explicit unsupported
inputs. Non-null semantic supersession requires a verified prior history that
this initial boundary does not establish; it stays blocked rather than invented.

`freeze_authority` writes core G1 rule/timing/guidance/blocker records, exact
predecessor/consumption/production links and analysis bindings. The
`u09_authority` extension retains draft-only status, Legal ownership, the exact
interpretation pointers, claimed candidate scopes/dispositions, blocker links
and supported component assessments. These are supplemental accounting values,
not new graph record types. A legal role is a condition for later factual testing,
not an assertion about every scoped system. Exceptions remain captured conditions,
not approved exemptions. No operational due dates are generated.

`validate_authority` independently rereads Stage 01/02, journal and exchange,
recomputes the Stage 03 projection and rejects changes even if all edited snapshot
hashes are rebuilt. Format checking/quote matching verifies binding and explicit
prerequisites; it does not prove legal meaning. The skill must inspect qualifiers
and surrounding paragraphs before proposing a rule. Legal retains final
interpretations and unresolved draft questions; their delivery and final rendering
remain later units. An unresolved Legal blocker cannot become normal publication.

Verification and limitations: [U09 report](verification/u09.md). Synthetic
fixtures prove this boundary, not actual Article 50 obligations or company
compliance. Existing source-access limitations remain visible.
